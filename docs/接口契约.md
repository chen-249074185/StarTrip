# 接口契约

> 前后端 / 各节点共同遵守的"形状"，防止各写各的。改动请先改这里再改代码。

## 1. 图状态（TripState）—— 谁写谁读

| 字段 | 类型 | 写入方 | 读取方 | 说明 |
|---|---|---|---|---|
| `user_input` | str | 入口 | planner | 原始需求 |
| `intent` | str | router | 条件边 | chat / clarify / plan |
| `history` | list[dict] | 入口/摘要 | planner | 多轮历史（经摘要压缩） |
| `session_id` | str | 入口 | 全链 | = checkpoint thread_id |
| `tasks` | list[dict] | planner | executor | 工具调用清单 |
| `tool_results` | dict | executor | retriever / reviewer | 按工具名归类，**值为列表**（同名工具聚合） |
| `rag_hints` | list[str] | retriever | reviewer | 攻略知识片段 |
| `trip_plan` | dict \| None | reviewer | 出口/落库 | 行程 JSON |
| `score` | float \| None | reviewer | 条件边 | 0~100（阈值 80） |
| `feedback` | str \| None | reviewer | planner | 不达标原因（回环） |
| `retry_count` | int | 条件边 | 条件边 | 回环已用次数，上限 3 |

## 2. 节点输入 / 输出契约

### planner（规划）
- 输入：`user_input`、`feedback`（可空）
- 输出：`tasks: list[dict]`
```json
[{"tool": "maps_text_search", "args": {"keywords": "必去景点", "city": "上海"}}]
```

### executor（执行）
- 输入：`tasks`
- 输出：`tool_results: dict`，key = 工具名，**同名工具结果聚合为数组**（防覆盖）；单工具失败记 `{"error": "..."}`，不抛断整节点
```json
{"maps_text_search": [{"name": "外滩", "location": "121.49,31.24", "cost": "", "rating": ""},
                      {"name": "豫园", "location": "121.49,31.23", "cost": "40", "rating": "4.6"}],
 "maps_weather": [{"days": ["..."], "raw": "..."}]}
```

### retriever（RAG）
- 输入：`tool_results`、`user_input`
- 输出：`rag_hints: list[str]`（topK，默认 5）

### reviewer（审查）
- 输入：`tool_results`、`rag_hints`、`user_input`
- 输出：`trip_plan: dict`、`score: float`、`feedback: str | None`
```json
{"days": [{"date": "D1", "spots": [{"name": "外滩", "time": "09:00-11:00",
  "transport": "地铁2号线", "budget": 0, "note": "早上去避人流"}], "budget_total": 320}]}
```

## 3. HTTP API

### POST /api/chat（SSE 流式）
- header：`Authorization: Bearer <JWT>`
- body：`{"session_id": "s1", "message": "..."}`
- 事件序列：
```
event: progress   data: {"stage": "planning",  "msg": "正在拆解任务..."}
event: progress   data: {"stage": "executing", "msg": "正在搜索景点（高德）..."}
event: progress   data: {"stage": "rag",       "msg": "正在检索攻略知识库..."}
event: progress   data: {"stage": "reviewing", "msg": "正在审查行程..."}
event: interrupt  data: {"tasks": [...], "msg": "请确认任务清单"}   # HITL，可选
event: result     data: {"trip_plan": {...}, "score": 88}
event: error      data: {"code": 500, "msg": "..."}
event: done       data: {}
```

### 其他
| 方法 | 路径 | 入参 | 返回 |
|---|---|---|---|
| GET | /health | - | `{status, pg, redis, llm, mcp}` |
| POST | /api/resume | `{session_id, tasks}` | SSE 续跑（HITL 确认后） |
| GET | /api/trips?session_id= | - | 行程列表 |
| GET | /api/trips/{id} | - | 行程详情 |
| GET | /api/prefs?session_id= | - | 偏好 |
| POST | /api/prefs | 偏好 JSON | ok |

## 4. 统一响应格式（非 SSE 接口）
```json
{"code": 0, "msg": "ok", "data": {}}
```
- `code=0` 成功；`401` 未登录；`403` 越权；`500` 服务端错误
