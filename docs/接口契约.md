# 接口契约

> 前后端 / 各节点共同遵守的"形状"，防止各写各的。改动请先改这里再改代码。

## 1. 图状态（TripState）—— 谁写谁读

| 字段 | 类型 | 写入方 | 读取方 | 说明 |
|---|---|---|---|---|
| `user_input` | str | 入口 | planner | 原始需求 |
| `intent` | str | router | 条件边 | chat / recommend / plan |
| `city` | str | router | planner | 目的地（空则走推荐） |
| `season` | str | router | recommend | 当前季节（按日期计算） |
| `history` | list[dict] | router / remember | router / planner / reviewer | 最近 10 条消息（约 5 轮），单条截断 800 字 |
| `session_id` | str | 入口 | 全链 | 开启鉴权时为 `user_id:session_id`（Checkpoint thread_id） |
| `tasks` | list[dict] | planner | executor | 工具调用清单 |
| `tool_results` | dict | executor | retriever / reviewer | 按工具名归类，**值为列表**（同名工具聚合） |
| `rag_hints` | list[str] | retriever | reviewer | 攻略知识片段 |
| `trip_plan` | dict \| None | reviewer | 出口/落库 | 行程 JSON |
| `score` | float \| None | reviewer | 条件边 | 0~100（阈值 80） |
| `trip_id` | int \| None | persist | 出口 | 落库后的 trips.id |
| `feedback` | str \| None | reviewer | planner | 不达标原因（回环） |
| `retry_count` | int | 条件边 | 条件边 | 回环已用次数，上限 3 |

## 2. 节点输入 / 输出契约

### planner（规划）
- 输入：`user_input`、`feedback`（可空）、`history`、`city`
- 输出：`tasks: list[dict]`
```json
[{"tool": "maps_text_search", "args": {"keywords": "必去景点", "city": "上海"}}]
```

### confirm（执行前确认，HITL）
- 输入：`tasks`、`retry_count`
- 输出：`tasks`（resume 后用用户提交的清单覆盖）
- interrupt payload：`{"tasks": [...], "msg": "请确认任务清单"}`
- 触发条件：`HITL_ENABLED=true` 且首次规划（`retry_count <= 1`）且 `tasks` 非空；回环重试不再打断

### executor（执行）
- 输入：`tasks`
- 输出：`tool_results: dict`，key = 工具名，**同名工具结果聚合为数组**（防覆盖）；单工具失败记 `{"error": "..."}`，不抛断整节点
```json
{"maps_text_search": [{"name": "外滩", "location": "121.49,31.24", "cost": "", "rating": ""},
                      {"name": "豫园", "location": "121.49,31.23", "cost": "40", "rating": "4.6"}],
 "maps_weather": [{"days": ["..."], "raw": "..."}]}
```

### retriever（RAG）
- 输入：`tool_results`、`user_input`
- 输出：`rag_hints: list[str]`（topK，默认 5）

### reviewer（审查）
- 输入：`tool_results`、`rag_hints`、`user_input`、`history`（最近对话）
- 输出：`trip_plan: dict`、`score: float`、`feedback: str | None`
```json
{"days": [{"date": "D1", "spots": [{"name": "外滩", "time": "09:00-11:00",
  "transport": "地铁2号线", "budget": 0, "note": "早上去避人流"}], "budget_total": 320}]}
```

### remember（收尾）
- 输入：`reply`、`trip_plan`、`history`
- 输出：`history`（追加一条 assistant 消息，含回复 + 行程摘要）
- 说明：每轮只执行一次，回环（reviewer → planner）期间不写历史

### persist（行程落库）
- 输入：`trip_plan`、`score`、`session_id`、`city`
- 输出：`trip_id: int`（写 `trips` 表）
- 说明：仅在有行程时写；写失败只记日志，不影响回复；`TRIP_PERSIST_ENABLED=false` 可关闭

## 3. HTTP API

### POST /api/chat（SSE 流式）
- header：`Authorization: Bearer <JWT>`（`AUTH_ENABLED=true` 时必填）
- body：`{"session_id": "s1", "message": "..."}`
- 记忆：`session_id` 即 Checkpoint `thread_id`，同一会话自动加载上一轮 `history` 并注入 planner/reviewer
- 事件序列：
```
event: progress   data: {"stage": "planning",  "msg": "正在拆解任务..."}
event: progress   data: {"stage": "executing", "msg": "正在搜索景点（高德）..."}
event: progress   data: {"stage": "rag",       "msg": "正在检索攻略知识库..."}
event: progress   data: {"stage": "reviewing", "msg": "正在审查行程..."}
event: interrupt  data: {"tasks": [...], "msg": "请确认任务清单"}   # HITL 暂停，本次不推 result
event: done       data: {}
# 用户在 POST /api/resume 提交任务清单后，继续推 progress / node / result / done
event: result     data: {"trip_plan": {...}, "score": 88}
event: error      data: {"code": 500, "msg": "..."}
event: done       data: {}
```

### 其他
| 方法 | 路径 | 入参 | 返回 |
|---|---|---|---|
| POST | /api/auth/login | `{username, password}` | `{access_token, token_type, username}` |
| GET | /api/auth/me | Bearer token | `{user_id, auth_enabled}` |
| GET | /health | - | `{status, pg, redis, llm, mcp, checkpoint, tracing, auth}` |
| POST | /api/resume | `{session_id, tasks}` | SSE 续跑（HITL 确认后；`tasks` 空则沿用原清单） |
| GET | /api/trips?session_id=&limit= | - | 行程列表（按 user+session 隔离） |
| GET | /api/trips/{id}?session_id= | - | 行程详情（不属于该 session 返回 404） |
| GET | /api/prefs?session_id= | - | 偏好（未实现） |
| POST | /api/prefs | 偏好 JSON | ok（未实现） |

## 4. 统一响应格式（非 SSE 接口）
```json
{"code": 0, "msg": "ok", "data": {}}
```
- `code=0` 成功；`401` 未登录；`403` 越权；`500` 服务端错误

## 5. 鉴权约定
- `AUTH_ENABLED=false`：向后兼容，`/api/chat`、`/api/resume` 不需要 token
- `AUTH_ENABLED=true`：必须带 `Authorization: Bearer <JWT>`；`/health`、`/api/config`、`/api/auth/login` 公开
- `thread_id = {user_id}:{session_id}`，不同用户即使 `session_id` 相同也互相隔离
- token：HS256，`sub=user_id`，默认 120 分钟过期；`JWT_SECRET` 未配置时服务拒绝启动
